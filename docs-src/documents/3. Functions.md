title: 3. Functions
---

There are a few built in functions that let you operate on schemas.

## st.write

Writes the data from the provided schema and object into a newly allocated buffer.

If serialization fails, throws an error with the access path that failed to serialize.

```ts
const User = st.object({
    name: st.string(st.u8()),
    age: st.u32(),
})

const data: ArrayBuffer = st.write(User, {
    name: "nnilky",
    age: 26,
})
```


## st.writeInto

This lets you write into an existing buffer, returning the amount of bytes written.

Intended for use with WASM/WebGL like contexts or for direct byte manipulation.
```ts
const buffer = new ArrayBuffer(32);
const User = st.object({
    name: st.asAscii(st.fixedBytes(16)),
    age: st.u32(),
})

let offset = 0;
offset += st.writeInto(buffer, offset, User, {
    name: "nnilky",
    age: 26
})
offset += st.writeInto(buffer, offset, User, {
    name: "nnilky",
    age: 26
})
```

## st.read

Lets you read a defined schema from an ArrayBuffer, allowing trailing space on the end.

If serialization fails, throws an error with the access path that failed to deserialize.

```ts
const data: ArrayBuffer = ...
const User = st.object({
    name: st.string(st.u8()),
    age: st.u32(),
})

const user: User = st.read(User, data)

// optional offset for reading into a larger ArrayBuffer
const user: User = st.read(User, data, 0)
```

## st.createReaderContext


A helper to create a reader context used by `Serializer.read`

This is used in [examples/wav.ts](https://github.com/Ben-Brady/structo-ts/blob/main/examples/wav.ts) to allow reading declartively

```ts
const buffer: ArrayBuffer = ...
const ctx = st.createReaderContext(buffer);

let chunks: Chunk[] = [];
while (ctx.offset < file.data.byteLength) {
    // ctx.offset is advanced with each read
    const chunk = Chunk.read(ctx)
    chunks.push(chunk);
}
```

> This is unstable and might change later, I'm not happy with this API
> The only reason this exists is st.read does not provide a way to see how much data was read

## st.estimateSize

Gives you an estimate for how much size a value will take up, this is useful for preallocation.

Additionally, it's a useful utility when writing your own serializers, see [Writing your Own Serializers](./5.%20Writing%20Your%20Own%20Serializers.md).

```ts
const User = st.object({
    username: st.string(st.u32()),
    createdAt: st.u32(),
});

st.estimateSize(User, {
    username: "nnilky",
    createdAt: 1794938926,
});
// 18
```

## st.Infer

Lets you infer the type of a schema, similar to `z.infer` from zod.

```ts
const User = st.object({
    username: st.string(st.u32()),
    createdAt: st.u64BigInt(),
})

type User = st.Infer<typeof User>
// expands to
type User = {
    username: string,
    age: bigint,
}
```

The convention is to write them before the type like this:

```ts
type User = st.Infer<typeof User>
const User = st.object({
    username: st.string(st.u32()),
    createdAt: st.u64BigInt(),
})
```
