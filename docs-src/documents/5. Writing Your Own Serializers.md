---
title: 5. Writing Your Own Serializers
---

Writing your own serializers is incredibly easy, just modifying some state and reading/writing some views.

I would recommend looking at the implementation of `st.u32`, `st.object` and `st.array` for a better idea on how to do these, as these types have extremely simple implementations.

```ts
function bytes(size: number): Serializer<UInt8Array> {
    return {
        // Specifying the size lets you allocate the type in advance
        // Also allowing support for types that require a fixed size
        size: size,
        write: (ctx, value) => {
            // Ensure that there is enough space ahead of the current pointer to write to
            ctx.reserve(size);

            // Write the data to the underlying buffer using ctx.bytes, a Uint8Array of ctx.buffer
            ctx.bytes.set(value, ctx.offset);

            // Increment the data point so anything writen after doesn't overrite this
            ctx.offset += size;
        },
        read: (ctx) => {
            // Read the data from ctx.bytes buffer we are given
            const value = ctx.bytes.slice(ctx.offset, ctx.offset + size);
            // Increment the point to the end of the data
            ctx.offset += size;
            return value;
        },
    };
}

st.object({
    id: bytes(8),
});
```

`WriterContext` and `ReaderContext` mostly overlap, with the only difference being that `WriterContext` has access to .reserve

## Object Error Reporting

`pushPath`/`popPath` are provided to help give proper error messages when encoding objects and arrays.

```ts
for (let i = 0; i < value.length; i++) {
    ctx.pushPath(i);
    type.write(ctx, value[i]);
    ctx.popPath();
}
```

The API is entirely optional to use, your code will still work fine without it. But it does provide a better experience when things go wrong.

## Testing

When writing a custom serializer, it's a good idea to make sure it doesn't break

If your using a library that's jest compatible, you can use `st.createTestingUtils` to get a set of helpers to make testing easier. If you want to an example of serializers see [the standard library](https://github.com/Ben-Brady/structo-ts/blob/main/src/object/object/object.test.ts).

```ts
import { st } from "@nnilky/structo";
import { describe, expect, it } from "test-library";
const { assertEncodesAndDecodes } = st.createTestingUtils(expect);

describe("st.object", () => {
    it("encodes correctly", () => {
        assertEncodesAndDecodes({
            serializer: st.object({
                a: st.u8(),
                b: st.u8(),
            }),
            value: { a: 1, b: 2 },
        });
    });
});
```
